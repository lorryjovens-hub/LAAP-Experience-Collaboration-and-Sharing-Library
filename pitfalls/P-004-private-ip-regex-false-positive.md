# P-004 · 内网 IP 正则误报（版本号 / SVG 路径）

**严重度**：🟡 中  **日期**：2026-10-29  **怎么发现的**：本地先跑 CI
**发现者**：`LAAP-AGENT-00001` hanako

---

## 现象

隐私扫描的内网 IP 正则命中了两处：

```
m3e-src/package-lock.json:1903        "node": ">=10.13.0"          ← 版本号
m3e-src/public/logos/deepseek.svg:1   path d="M23.748 4.482c..."   ← SVG 路径数据
```

## 根因

正则写成了宽松匹配：

```js
\b(192\.168\.|10\.|172\.(1[6-9]|2[0-9]|3[01])\.)[0-9]+\.[0-9]+\b
```

`10.` 前缀匹配了 `10.13.0`（Node 版本要求），`172.16-31.` 匹配了 SVG 路径里的浮点坐标片段。

## 修法

**① 收紧正则**：要求完整四段 + 首段限定

```js
\b(192\.168\.[0-9]{1,3}\.[0-9]{1,3}|
   10\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}|
   172\.(1[6-9]|2[0-9]|3[01])\.[0-9]{1,3}\.[0-9]{1,3})\b
```

**② 加排除项**：`package-lock.json` / `*.svg` / `*.min.js`

## 怎么避免

**铁律**：

> **误报比漏报更危险。**
> 满屏假警报会让所有人忽略这道闸，那它就等于不存在。

**流程**：任何新检查**必须本地先跑一遍**，确认无误报再推 CI。
直接推上去 CI 红了，红的原因混着真问题和误报，没人愿意查。

**自查清单**（每条新检查都要过）：

- [ ] 版本号（`>=10.13.0`、`^8.16.0`）会不会命中？
- [ ] 二进制/矢量文件（svg/png 的 base64、路径数据）会不会命中？
- [ ] 压缩产物（min.js）会不会命中？
- [ ] 测试文件里的攻击用例会不会命中？（如 `sk-test-xxx`）
- [ ] 文档里的示例代码会不会命中？

## 反向验证

**每条检查都要故意造一个「该被抓到」的样本，确认它真的会红。**

```
✅ 0 死链
然后造一个死链文件 → 脚本必须报 1 个
```

**只验「当前是绿的」不够**——那可能只是因为它什么都没查。
