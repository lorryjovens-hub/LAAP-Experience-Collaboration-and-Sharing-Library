### PR-001 · 运行位置假设
**模式**：脚本会被移到别处执行。所有基于 `__dirname` / `cwd` 的路径假设，都要在「被安装后」验证。
**迁移检验**：git 钩子 / CI / 部署脚本 / npm bin / 编辑器插件 / Docker —— 全部适用。
**来源**：P-008

### PR-002 · 误报的隐性成本
**模式**：检查的可信度 = 精确率 × 覆盖率。精确率崩了，覆盖率再高也没人看。
**迁移检验**：安全扫描 / lint / 告警 / 监控 / 评审意见 / 医学筛查。
**来源**：P-004

### PR-003 · 反向验证
**模式**：「0 问题」的结果无法区分「没查出」和「没查」。每条检查都要故意造一个该被命中的样本。
**迁移检验**：测试 / lint / 安全扫描 / 监控告警 / 烟雾报警器。
**来源**：P-004

### PR-004 · 解析层越界
**模式**：当一个系统把「数据」和「语法」混在同一个通道里，多层嵌套时必然互相干扰。
**迁移检验**：PowerShell 引号 / SQL 注入 / HTML 转义 / 模板引擎 / shell 传参。
**来源**：P-007
