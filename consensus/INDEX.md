# 领域共识 · INDEX

> **共识不是「我们觉得 X 重要」，是「遇到 X 的信号时做 Y」。**

---

## 质量与检查

### C-001 · 误报比漏报更危险
**信号**：新加任何自动检查（CI / lint / 安全扫描）
**判断**：满屏假警报会让所有人忽略这道闸。**必须本地先跑，确认无误报再推 CI。**
**理由**：[P-004](../pitfalls/P-004-private-ip-regex-false-positive.md)

### C-002 · 检查要反向验证
**信号**：写完一条检查显示「0 问题」
**判断**：那可能只是因为它什么都没查。**必须故意造一个「该被抓到」的样本，确认它真的会红。**
**理由**：只验「当前是绿的」无法区分「没查出问题」和「根本没查」。

### C-003 · 没人看的地方会烂掉
**信号**：代码/配置处在「不会被经常查看」的位置（CI 日志、错误分支、注释、legacy/）
**判断**：这些地方的问题会长期存在不被发现。**要么让机器盯，要么定期主动查。**
**理由**：[P-003](../pitfalls/P-003-electron-mirror-env-not-config.md) — CI 挂了很久没人知道

## 工程实践

### C-004 · 超过 3 行的脚本写成文件
**信号**：要在 PowerShell 里嵌 Python / Node / JSON
**判断**：直接写临时文件执行。内联省下的几秒，会在引号地狱里加倍还回来。
**理由**：[P-007](../pitfalls/P-007-powershell-inline-encoding.md)

### C-005 · 脚本的运行位置 ≠ 开发位置
**信号**：git 钩子、CI 脚本、部署脚本用了 `__dirname` / 相对路径
**判断**：用 `git rev-parse --show-toplevel` 这类不依赖位置的方法。**装上后必须真实跑一次。**
**理由**：[P-008](../pitfalls/P-008-git-hook-relative-path.md)

## 知识本身

### C-006 · 记「怎么发现的」，不只记「怎么修的」
**信号**：写坑/经验条目
**判断**：「怎么修的」只救一次，「怎么发现的」救每一次——它决定下次该在哪里设卡。
**理由**：本库写作铁律第二条

### C-007 · 写错比不写好
**信号**：犹豫要不要写一条不太确定的经验
**判断**：写。一条写错的会被纠正，纠正过程本身就是知识；一条没写的会一直被重复踩。
**理由**：本库写作铁律第五条

---

*共识的价值不在于「我们知道什么」，在于「我们遇到情况时会怎么做」。*
